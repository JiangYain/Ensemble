# Marks

- `cursor.svg`: Cursor 2D cube, light-background variant, from the [official brand asset kit](https://cursor.com/brand).
- `pi.svg`: the [official Pi logo download](https://pi.dev/logo-auto.svg).
- `codex.svg`: the Codex app logo, in colour — the blossom outline holding a white `>_` prompt, filled with a vertical lavender-to-blue gradient `#B1A7FF → #7A9DFF → #3941FF`. The outline and the `>_` are the paths of the `codex` icon, and the gradient values are those of the `codex-color` icon, of [`@lobehub/icons-static-svg`](https://www.npmjs.com/package/@lobehub/icons-static-svg) 1.102.0 (MIT, [lobehub/lobe-icons](https://github.com/lobehub/lobe-icons)); the geometry is unchanged (the same path data as that package's `codex.svg`, except that the two `>_` start points are written as absolute coordinates). Ensemble only recomposed it: the whole outline carries the gradient and the `>_` is painted on top as separate white shapes — no white tile, no cut-out, so the prompt stays white on any surface. It is an interface rendering of the official gradient, not a byte-exact official file; measured against the logo the Codex desktop app itself ships (`codex-app-ga-logo.png`, read from the installed app 26.1106, 2026-11-15) the mean hue differs by 3° and the mean channel error is about 3 %. OpenAI's [design guidelines](https://openai.com/brand/) and trademark terms apply to the mark; OpenAI does not endorse Ensemble.
- `claude-code.svg`: the Claude Code mascot from [Simple Icons](https://github.com/simple-icons/simple-icons/blob/fd14b05fa2a533f1f0cfa7f297971d82947beeb9/icons/claudecode.svg), shown in the Claude Code brand color; Anthropic's [trademark guidelines](https://www.anthropic.com/legal) apply to the mark.

The app is light-only, so the light version is the right one. In the UI it is written next to the name "OpenCode", spelled as the page asks. **Terms.** The page's *Trademarks* section reads: "OpenCode and the OpenCode logo are trademarks of Anomaly. Do not use them to suggest that Anomaly endorses or sponsors you, in your product or company name, or on merchandise without permission." Its *Integrations* section lets plugins and tools that work with OpenCode say so (with a badge or partner lockup, neither of which Ensemble uses). That page publishes brand guidelines, not an open-source licence for the files, so the permission rests on those guidelines; written confirmation, if wanted, is a question for `press@anoma.ly` (the address the page gives). **Where Ensemble falls short of the guidelines.** The page sets a minimum of 16 × 20 px with a 4 px stroke ("any smaller and it blurs"), asks for scaling in 4 × 5 px steps so every edge lands on a whole pixel, and asks for two strokes of clear space (half the logo's width) on every side. It was rendered in Chrome at 12 / 16 / 19.5 / 24.7 / 31.2 px, at 1× and 2×, on 2026-11-16 and stays recognisable (dark frame, lighter inner panel) at every size. **Correction (2026-11-15, later the same day).** The first version of this policy also listed Codex as an official monochrome logo. That was wrong. The monochrome Codex file is the flat single-colour icon that icon libraries ship (lobehub's `codex`, svgl's `codex_light`/`codex_dark`; the file Ensemble used before is byte-identical to them), while the Codex app itself ships a lavender-to-blue gradient logo with a white `>_`. Two things that look like counter-evidence are not: the Codex IDE extension's store and activity-bar icons are the plain black-and-white OpenAI Blossom without a `>_` (the generic OpenAI mark on a different surface — VS Code tints activity-bar icons anyway), and OpenAI's brand page documents only the wordmark and the plain Blossom ("don't add any colors to the Blossom") and publishes no Codex product icon. What Ensemble drives is the Codex product (through the Codex app-server), so the logo of the Codex app is the one that stands for this harness; the colour is the one OpenAI's own app ships, not one Ensemble adds. The old entry's two citations (a theSVG page and a `backnotprop/orchestrator` README) could not confirm anything — the second page is empty — and are no longer cited.

### Git

The Git card's head icon (`.node.git .o-head .a-mark`) is the `git` icon in `src/web/components/Icons.tsx`: a small solid sharp-cornered diamond with a three-node fork cut out of it. It is a solid mark, not one of the stroked line icons of that file (the comment above `GitMark` explains why: a stroked diamond with a thin fork is unreadable at 12.6 px). Two things come from the official Git logo, and they are credited separately:

- **Colour.** `#F03C2E`, read directly from the fill of the official orange logo file [`Git-Logo-1788C.svg`](https://git-scm.com/images/logos/downloads/Git-Logo-1788C.svg) hosted on [git-scm.com](https://git-scm.com/community/logos) (Pantone 1788 C). Only the colour value is used; it lives in `brand.css`.
- **Composition.** The idea of a diamond with a three-node fork inside it is the idea of the [Git logo by Jason Long](https://git-scm.com/community/logos), which git-scm.com publishes under [CC BY 3.0 Unported](https://creativecommons.org/licenses/by/3.0/) (verified against that page and the [Wikimedia Commons record of the logo](https://commons.wikimedia.org/wiki/File:Git-logo.svg), 2026-11-15). The Ensemble shape is **redrawn by hand** from that composition alone, on a 24 grid for 12.6 px: sharp corners (the whole interface is square-cornered, so the diamond is too), square nodes turned 45°, a different node and line arrangement, one diagonal arm, knock-out line width chosen for pixel crispness. No file, path data or trace of the official logo is shipped. Because it is an adaptation of the composition, the attribution CC BY 3.0 asks for applies: *Git Logo by Jason Long, licensed under CC BY 3.0 (https://creativecommons.org/licenses/by/3.0/); changes: redrawn and simplified as a small interface icon.* The Git project does not endorse Ensemble.

Every colour above is applied only to the small identifying marks, never as a status, emphasis, or interactive colour: status and interaction keep the neutral palette of the rest of the UI.
